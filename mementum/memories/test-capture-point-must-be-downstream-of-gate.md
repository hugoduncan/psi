🔁 A suspected regression may be a coverage gap at the real gate, not a code bug. Task 242 chased a "retry footer suppressed by task-241 focus gate" regression; an existing E2E test (`rpc-prompt-provider-retry-state-publishes-footer-updated-test`) captured at a **pre-gate** seam — a plain `emit!` fn passed straight into `streams/start-progress-loop!` — so it never touched `rpc.events/emit-event!`/`focus-allows?`. The actual focus-gate boundary had zero coverage. The focused path was never broken; the fix was adding a test wired through the production emitter (`emit/make-request-emitter`), which routes through the real gate.

Rule: before trusting an E2E test to lock behaviour at a policy/gate boundary, verify its **capture point is downstream of that gate**. A green test hung on a pre-gate injection point proves the producer, not the gate — and its silence can be misread as evidence the gate is broken. Prove the gate test is non-vacuous by bypassing the gate and watching it fail (leaked frames).
