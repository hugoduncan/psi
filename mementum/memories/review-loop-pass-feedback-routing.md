🔁 Review workflows that execute follow-ups inside a multi-phase or multi-prompt pass need explicit pass-level feedback memory in deterministic routing, not a late re-read of task artifacts. Follow-up steps can clear `design-steps.md`/`steps.md`, so completion must route over recorded review outputs (for example `workflow/pass-feedback-routing`) with an explicit guarded loop-back. The routing operation must also be a validator: require at least one feedback input, require every value to be a string containing exactly one allowed `PASS_STATUS`, reject missing/duplicate/malformed/disallowed statuses with deterministic diagnostics, and route `REPEAT` iff any valid reply is actionable; never let empty or malformed feedback silently imply `DONE`.
