🔁 Review workflows that execute follow-ups inside a multi-phase pass need explicit pass-level feedback memory in deterministic routing, not a late re-read of task artifacts. Follow-up steps can clear `design-steps.md`/`steps.md`, so a final clarity/completion gate that only inspects current files may falsely complete even though a phase found `ACTIONABLE_FEEDBACK`. Prefer a locally comprehensible topology: run every phase in the pass, conditionally execute phase follow-ups, then route through a deterministic judge over the pass's review outputs (for example `workflow/pass-feedback-routing`) with an explicit guarded loop-back to the first phase. If the actor body is only a route host, use a constant actor plus the routing judge rather than duplicating the same routing operation twice.
