🔁 A fixed literal set of "known helper/infra session names" used to exclude sessions from some post-turn behaviour is drift-prone: every extension that spawns a turn-completing child session (runs an agent loop → fires `session_turn_finished`) must be enumerated, or it leaks in as a false input. Task 239's friction analyzer repeatedly caught AC5 exclusion gaps this way: workflow-step children (dynamic `"workflow <step-id> attempt"` names, needs `starts-with?`∧`ends-with?`, not a literal), then the `auto-session-name` extension's helper, plus its own `"friction-analysis"` name.

Design guidance: don't rely solely on a literal name set. Combine (1) extension-owned id-tracking atoms (authoritative for own/known helpers), (2) a dynamic predicate for pattern-named sessions, and (3) a literal-name backstop for cross-process/reload cases where atoms are empty. When adding an extension that runs turn-completing helper sessions, audit every consumer of `session_turn_finished` that filters infra sessions. (task 239)
