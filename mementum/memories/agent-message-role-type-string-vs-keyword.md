❌ Agent-core persists message `:role` (`"user"`/`"assistant"`/`"toolResult"`) and content-block `:type` (`"text"`/`"error"`) as **strings**, not keywords. Any consumer that compares them with `= :user` / `= :text` silently mis-behaves in production while keyword-shaped test fixtures make it pass. Task 239 hit this twice: round-7 `group-into-turns` compared `:role` to keyword `:user` (20 real turns collapsed to 1); round-10 `message-snippet`'s content-block `:type` filter was keyword-only (dropped string `"text"`/`"error"` blocks, losing the tool-error friction signal).

Rule: normalize before comparing — `(some-> role name)` / `(name type)` then test against the string (or a `#{"text" "error"}` set). Fixtures must use the real string-role/string-type shape (as elsewhere in the suite); keep one keyword-shape test only to pin backward tolerance. Same class as consumer-fixtures-must-match-producer-projection-shape, one layer down (field values, not container shape). (task 239)
