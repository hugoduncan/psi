🔁 Generic task-artifact resolvers that take `task-path`/`artifact-name` args must treat those args as untrusted file selectors. Worktree-root containment is too broad: `artifact-name` with `..` can read project-root files or sibling task artifacts. Resolve the worktree, task directory, and target artifact via real/canonical paths; require the task dir under the worktree and the target regular file under that task dir; reject absolute segments, `..` escapes, symlink escapes, missing paths, and non-regular files before `slurp`. Keep workflow policy out of the resolver (no marker/artifact specifics), but make the generic IO seam enforce the task-artifact boundary. Lock it with tests for absolute paths, `..` escapes, sibling-task reads, and directory artifacts.
