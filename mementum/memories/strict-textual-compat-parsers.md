🔁 For compatibility parsers that can trigger effects (especially tool execution), prefer a narrow strict contract over permissive recovery. Task 231 repeatedly churned on nested/literal `<tool_call>` markup before converging: tag-looking protocol markup inside parameter text is malformed/no-op, nested recovery is unsupported, malformed outer spans suppress inner execution, and later independent valid blocks still recover. This keeps invalid/ambiguous text visible as assistant prose instead of guessing and possibly executing unintended tools.
