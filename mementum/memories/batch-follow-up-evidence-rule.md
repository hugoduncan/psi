🔁 When a review workflow batches multiple review prompts before one follow-up, define follow-up scope by task-scoped evidence, not by current unchecked checklist state. Treat the preceding pass as the contiguous review-batch segment since the previous follow-up; use the parent of the oldest batch commit as baseline; candidates are diff-added unchecked checklist lines in the intended artifact (e.g. `design-steps.md`) that still exist unchecked. Exclude pre-existing, stale, checked, wrong-artifact, ambiguous, or unattributable items; leave them untouched and write a terse blocking note instead of guessing.
