🔁 A new psi extension must expose discovery + control through the canonical psi-tool surface, not only a slash command. Slash commands (`(:register-command api)`) are reachable from TUI/emacs by a human — they are NOT agent-reachable via psi-tool, so an agent can neither discover nor drive the capability.

The extension API has NO `:register-resolver`/`:register-mutation`. The sanctioned discover+invoke mechanism is `:register-operation` (deterministic operations, task 205): each `{:id "ns/name" :description … :handler (fn [{:keys [ctx args]}] → result-map)}` becomes listable via psi-tool `operation` `op:list` and invocable via `op:invoke` (and `/operations` / `/operation`). Register a no-side-effect `…/status` for discovery and `…/start`/`…/stop` (etc.) for control; have the slash command and the operations both call the same shared lifecycle fns so the surfaces never drift.

Invariant: `if ¬discoverable → halt`. When building/reviewing an extension, explicitly check "is this controllable/discoverable through the canonical agent surfaces?" — HTTP/behaviour tests passing does not prove the introspection contract holds. (dev-http/229 shipped without this and it was caught post-hoc.)
