❌ A consumer that reads a runtime projection with the wrong shape fails *silently* and the defect hides when its test fixture matches neither the real producer's shape. In task 238 the augmenter iterated `:turn-augmentation/history` as a flat vector reading `(:text entry)`, but the live producer (`dispatch_effects/build-augmentation-history-projection`) emits a **map** `{:message-count N :tail [{:index :role :content-types :snippet}]}`. So history-tail context (design-required for anaphora) was *always empty* in production — masked because `build-...-prompt-test` fed a hand-built flat vector `[{:role :text}]` matching neither the projection map nor its entry keys. Green test against a fixture the runtime never produces.

Rule: when testing a consumer of a cross-boundary projection, build the fixture from the **real producer's** shape (locate the producer fn, or share a projection helper) — never invent a plausible shape. Add regressions asserting real-shape input renders AND that the wrong/empty shape yields nothing, so a shape drift is caught. (task 238)
