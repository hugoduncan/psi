🔁 Workflow terminal result-text resolves through two divergent paths. Standalone `/delegate` (`canonical_workflows/execute-workflow-run` + `terminal-yielded-text`) keys strictly off `(last :step-order)` — the lexically-last step, run or not. The lifecycle delegate-gate path (`terminal_contract/terminal-result-envelope`) reverse-scans step-order for the actually-run terminal step (order-independent). Consequence (task 229): when a loop can terminate at one of several summary steps, the standalone path surfaces only the last-ordered summary's text; an earlier-ordered handback summary that actually ran yields empty standalone result text, while the lifecycle gate resolves it correctly. So step ORDERING in the `.edn` silently determines standalone output. When adding an alternate terminal summary, order the common/expected one last to keep standalone useful, accept the alternate's standalone degradation as known (lifecycle consumes it via the order-independent path), and document the degradation. Fixing the shared `(last :step-order)` resolution to be run-aware is the real fix but larger scope.
