🔁 Terminal yielded text must be selected from the executed terminal outcome, never declared step order. Task 229 exposed the split: standalone execution read `(last :step-order)`, while lifecycle delegation resolved the terminal step that actually ran; alternate terminal branches could therefore yield empty standalone output. Task 256 fixed the shared terminal-contract projection: use `:terminal-outcome :step-id` for a completed run, and yield no text for failed or cancelled outcomes even if a terminal step retained text. This makes alternate terminal summaries (including clean human handbacks) order-independent for standalone callers and delegates. When adding a terminal branch, prove accepted standalone and delegated yields select the executed branch; prove rejected/cancelled branches project `nil`, so downstream routing cannot consume unaccepted text.
