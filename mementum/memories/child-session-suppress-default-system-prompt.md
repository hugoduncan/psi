🔁 `psi.extension/create-child-session` with no `:prompt-component-selection` gives the child the **full default system prompt** — AGENTS.md context files, every skill `when-to-use` contribution, all extension prompt contributions, all tool prompt fragments (`normalize-prompt-component-selection` nil → full assembly). For a constrained helper session whose behaviour must be governed by an *authored* prompt only, this silently injects conflicting guidance.

Suppress it explicitly (mirror `auto-session-name`): `:prompt-component-selection {:agents-md? false :extension-prompt-contributions [] :tool-names ["bash"] :skill-names [] :components #{}}`. Note `:tool-names` here controls only which *tool-prompt fragments* are assembled — the actual tool grant is the separate `:tool-ids ["bash"]` param. Also: `create-child-session` does **not** destructure `:worktree-path` (silent dead param) — the child gets cwd via parent-worktree inheritance; don't pass a `:worktree-path` expecting it to take effect.
