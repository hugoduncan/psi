## Macro-generated vars (unresolved-var warnings)

clj-kondo's jar analysis never macroexpands a library's private macros, so vars
generated by them are absent from namespace analysis and produce
`Unresolved var` warnings at call sites even when the require is correct.

- http-kit 2.8.0's `org.httpkit.client/get|post` are generated by its private
  `defreq` macro (plain `defn`s like `request` analyze fine).
- Analysis-level fix (no suppression): add to the per-library import config
  `.clj-kondo/imports/http-kit/http-kit/config.edn`:
  `{:lint-as {org.httpkit.client/defreq clojure.core/def}}` — each `(defreq verb)`
  is then analyzed as `(def verb)`, registering the full verb set. Verified
  against clj-kondo 2025.09.19 + http-kit 2.8.0; a genuine bogus `http-client/…`
  var still warns (this is resolution, not silencing).
- The `:namespaces {ns {var {:defined-by …}}}` var-declaration facility does NOT
  exist in clj-kondo 2025.09.19 — `:defined-by` is analysis output, not config
  input (silently ignored). `:lint-as` or a `:macroexpand` hook are the real
  facilities.

## Import dir is gitignored

`.clj-kondo/imports/` is gitignored, so a per-library import change is uncommittable
until you add `.gitignore` negation (e.g. keep `**/.clj-kondo/imports/*` but
`!`-allow the specific library dir). Root `.clj-kondo/config.edn` stays clean.

## Cache caveats (silent staleness)

- Cache entries are ns-keyed, not version-keyed: a version-mismatched stale cache
  lints silently clean. Pin the jar version when rebuilding.
- `--dependencies`-built caches record only the internal path (e.g.
  `org/httpkit/client.clj`) in `~:filename` — no jar path/version — so you cannot
  grep the cache for the jar version.
- Jar skip markers (`.clj-kondo/.cache/v1/skip/{jar}.*`) make a re-run print
  "already linted, skipping" and keep the stale ns cache. Force a rebuild with
  `rm -f <skip-marker> <ns transit file>` then re-run `--dependencies`.
- If the `:lint` alias already lists `--lint` paths, an extra
  `--lint <file>` accumulates rather than narrowing — the repo-wide surface runs.

## Verification

`bb lint` (≡ `clojure -M:lint`) is cache-dependent and local-only; CI with no cache
never analyzes dependency jars and is trivially clean regardless. Regression-proof a
per-library registration with a hermetic integration test (temp cache, pinned jar),
not via the repo lint surface.
