# Design Follow-ups

- [x] **AR1** Pin the post-implementation architecture review gate to the existing review-loop architecture: the `review-implementation-architecture` skill should be executed through the shared `review-step` / `review-follow-up-steps` machinery as a workflow-local gate in `reduce-architectural-complexity`, with the selected Gordian target and task artifacts in context. The design must also state that this architecture-specific gate should not be implemented as a bespoke review loop and should not broaden the generic `review-task-implementation` workflow for unrelated tasks unless a separate general review-design decision explicitly does so.

- [x] **AMB1** Pin the no-target / uninterpretable-`architecture-targets` selector control contract: specify the exact final `PASS_STATUS` token emitted by `select-and-create`, how that token maps through `workflow/pass-status-routing`, and the `:on` route that completes the workflow without running design/plan/test-net/implementation steps.
- [x] **AMB2** Define how each selected architecture candidate type maps to concrete target/source areas recorded in the generated task and `characterization-baseline.edn`: namespace, family, pair, and community candidates must have an unambiguous file/namespace membership rule so clean-baseline dirt checks, coverage review, diff-gate classification, and blast-radius limits all inspect the same area.
- [x] **AMB3** Pin the task-local baseline/evidence artifact contract for generated tasks: exact filenames, formats, and worktree-root-relative references for the before diagnose snapshot used by `gordian gate`, the `architecture-targets` ranking output, optional `target-issues` output, and any after/compare artifacts required by validation.
- [x] **AMB4** Choose the exact implementation architecture review skill identity and filesystem path (for example `.psi/skills/review-implementation-architecture/SKILL.md`) and require the workflow's `review-step` invocation to use that exact `:skill` value, rather than leaving the name as a candidate.
- [x] **AMB5** Pin the post-implementation review sequence precisely: decide whether `reduce-architectural-complexity` calls the generic `review-task-implementation` workflow plus an architecture gate, or replaces it with explicit workflow-local `review-step` gates for implementation-architecture, test-shaper, and code-shaper; state whether task-implementation-review, task-test-review, and docs review are included or intentionally omitted.

- [x] **INC1** Align the `architecture-targets` selector/output contract with the actual authoritative EDN artifact shape: pin selection to `bb gordian architecture-targets --edn` and top-level `:winner` / `:candidates` (or explicitly support both envelopes), remove the conflicting `:architecture-target-ranking` requirement unless the command really emits it, and ensure tests exercise the real/expected envelope so valid current output does not take the uninterpretable no-target route.
- [x] **INC2** Resolve the validation-artifact timing mismatch after `implement-task`: either require `implement-task` / the generated task checklist to produce `after-diagnose.edn`, `after-architecture-targets.edn`, `architecture-compare.edn`, and `architecture-gate.edn` before yielding implementation-complete, or add an explicit workflow-local validation-capture gate before the post-implementation review-step chain. The design should state how missing/failed validation artifacts route and tests should lock that producer-before-review ordering.
- [x] **INC3** Synchronize the acceptance-test criteria with the explicit six-gate post-implementation review sequence: tests must lock not only `review-implementation-architecture`, `test-shaper`, and `code-shaper`, but also `task-implementation-review`, `task-test-review`, `review-task-docs`, and their required order/contexts, unless the design intentionally removes or narrows those gates.
