# Design follow-up steps

- [ ] ARCHITECTURE: Key Question 3 proposes an `:each` fixture as a safety-net sweep for leaked temp prefixes; `clojure-coding-standards` explicitly disallows `use-fixtures` in this project ("No use-fixtures - Prefer `(with-xxx [args] ...)` macros for setup/teardown"). If a safety-net sweep is pursued, the design must steer plan/steps toward a `with-xxx`-style or explicit-call mechanism instead of `clojure.test/use-fixtures :each`, not toward a fixture.
- [ ] AMBIGUITY: In Scope item for `test_support.clj` says "consider adding OS-level temp dir auto-cleanup (e.g., `Files/deleteIfExists` in finally)" — clarify whether this auto-cleanup mechanism is required in-scope work or an optional suggestion the implementer may skip if per-caller `finally` cleanup alone satisfies the acceptance criteria.
- [ ] AMBIGUITY: Acceptance Criterion 1 ("no directories matching the listed prefixes exist under `/tmp/` or any test repo directory") doesn't define what counts as "any test repo directory", and its single-run wording doesn't say whether verification is a single `bb test` run or the repeated-run non-accumulation property described in Constraints ("running `bb test` repeatedly should not accumulate..."). Clarify the verification protocol (single run vs. N repeated runs) and what directories are in scope for the check.
- [ ] INCONSISTENCY: Acceptance Criterion 3(c) allows a prefix to be addressed by "removed if the test is no longer needed", but Constraints say "Do not change test behaviour or assertions — only fix cleanup paths" and Out of Scope says "Adding new tests (only fix cleanup in existing tests)". Removing a test is a behaviour change the Constraints/Out-of-Scope wording forbids. Resolve which governs: either drop AC3(c)'s removal option, or explicitly carve out test removal as a permitted exception to the cleanup-paths-only constraint.
- [ ] INCONSISTENCY: The In-Scope `test_support.clj` item suggests `Files/deleteIfExists` for OS-level temp dir auto-cleanup, but Constraints state "`delete-recursively!` is the established cleanup primitive — reuse it". `Files/deleteIfExists` cannot delete a non-empty directory (throws `DirectoryNotEmptyException`), so it cannot actually clean up populated `temp-cwd`/`temp-session-root` trees and conflicts with the stated primitive-reuse constraint. Replace the example with `delete-recursively!`-based cleanup or otherwise reconcile the two statements.
- [ ] INCONSISTENCY: The Context section lists a single prefix `psi-agent-session` for `test_support.clj`, but the actual code (`temp-cwd`/`temp-session-root`) uses two distinct prefixes, `"psi-agent-session-test-"` and `"psi-agent-session-store-"`. Update the Context section (or AC3's "9 prefixes" framing) to reflect both literal prefixes so later steps know to check/fix both call sites.
