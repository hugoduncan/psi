# Design follow-up steps

- [x] ARCHITECTURE: Key Question 3 proposes an `:each` fixture as a safety-net sweep for leaked temp prefixes; `clojure-coding-standards` explicitly disallows `use-fixtures` in this project ("No use-fixtures - Prefer `(with-xxx [args] ...)` macros for setup/teardown"). If a safety-net sweep is pursued, the design must steer plan/steps toward a `with-xxx`-style or explicit-call mechanism instead of `clojure.test/use-fixtures :each`, not toward a fixture.
- [x] AMBIGUITY: In Scope item for `test_support.clj` says "consider adding OS-level temp dir auto-cleanup (e.g., `Files/deleteIfExists` in finally)" — clarify whether this auto-cleanup mechanism is required in-scope work or an optional suggestion the implementer may skip if per-caller `finally` cleanup alone satisfies the acceptance criteria.
- [x] AMBIGUITY: Acceptance Criterion 1 ("no directories matching the listed prefixes exist under `/tmp/` or any test repo directory") doesn't define what counts as "any test repo directory", and its single-run wording doesn't say whether verification is a single `bb test` run or the repeated-run non-accumulation property described in Constraints ("running `bb test` repeatedly should not accumulate..."). Clarify the verification protocol (single run vs. N repeated runs) and what directories are in scope for the check.
- [x] INCONSISTENCY: Acceptance Criterion 3(c) allows a prefix to be addressed by "removed if the test is no longer needed", but Constraints say "Do not change test behaviour or assertions — only fix cleanup paths" and Out of Scope says "Adding new tests (only fix cleanup in existing tests)". Removing a test is a behaviour change the Constraints/Out-of-Scope wording forbids. Resolve which governs: either drop AC3(c)'s removal option, or explicitly carve out test removal as a permitted exception to the cleanup-paths-only constraint.
- [x] INCONSISTENCY: The In-Scope `test_support.clj` item suggests `Files/deleteIfExists` for OS-level temp dir auto-cleanup, but Constraints state "`delete-recursively!` is the established cleanup primitive — reuse it". `Files/deleteIfExists` cannot delete a non-empty directory (throws `DirectoryNotEmptyException`), so it cannot actually clean up populated `temp-cwd`/`temp-session-root` trees and conflicts with the stated primitive-reuse constraint. Replace the example with `delete-recursively!`-based cleanup or otherwise reconcile the two statements.
- [x] INCONSISTENCY: The Context section lists a single prefix `psi-agent-session` for `test_support.clj`, but the actual code (`temp-cwd`/`temp-session-root`) uses two distinct prefixes, `"psi-agent-session-test-"` and `"psi-agent-session-store-"`. Update the Context section (or AC3's "9 prefixes" framing) to reflect both literal prefixes so later steps know to check/fix both call sites.
- [x] INCONSISTENCY: The Context section attributes six prefixes (`existing-path`, `feature-attached`, `feature-diverged`, `feature-merge`, `feature-rebase`, `legacy-create-branch`) and the In-Scope bullet attributes the `linked-worktree-path` helper and the `with-null-context` macro to `components/history/test/psi/history/git_test.clj`, but in the actual code both `linked-worktree-path` and `with-null-context` are defined in, and all six prefixes only appear in, `components/history/test/psi/history/git_worktree_test.clj` — a sibling file `git_test.clj`'s own docstring says worktree/branch-operation tests were deliberately "split from `git_test.clj`...to satisfy the file-length commit check" into. `git_test.clj` itself contains none of this worktree machinery or these prefixes. Implementers following the In-Scope bullet's literal file reference would look in the wrong file and find nothing to fix. Correct the Context/In-Scope file references to `git_worktree_test.clj` (the file that actually needs the gap analysis and any fixes), or otherwise reconcile design.md with where this code actually lives.
- [ ] SCOPE_QUESTION: AC1 requires no leaked `psi-agent-session-test-`/`psi-agent-session-store-` directories after a single `bb test` run (a whole-suite property), but `test-support/temp-cwd` and `test-support/temp-session-root` are called directly — with zero `delete-recursively!`/`with-temp-session-root` cleanup — from at least 13 test files outside the frozen In-Scope list (e.g. `commands_test.clj`, `commands_session_profile_test.clj`, `commands_speed_effort_test.clj`, `extension_installs_test.clj`, `extension_manifest_activation_test.clj`, `project_nrepl_extension_install_test.clj`, `workflow_manifest_activation_test.clj`, `extensions_io_test.clj`, `commands_builtin_specs_test.clj` in `agent-session`, plus `app_runtime_bootstrap_test.clj` and `extension_install_startup_test.clj` in `app-runtime`). The In-Scope `test_support.clj` bullet's primary mechanism (per-caller `finally` cleanup) cannot satisfy AC1 without editing those un-listed caller files, and the only mechanism that could satisfy AC1 purely within the 4 listed files is a centralized `with-xxx`-style safety net inside `test_support.clj` — which the design currently marks optional/not-required rather than mandatory. A human should decide whether the In-Scope file list is meant to be exhaustive (in which case AC1 is very likely unsatisfiable unless the safety-net mechanism becomes a required part of scope) or whether the listed caller files are illustrative and additional callers are implicitly in scope.
