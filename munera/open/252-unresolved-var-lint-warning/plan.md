# Task plan — 252-unresolved-var-lint-warning

Contract: design.md (Mechanism, Constraints, Acceptance AC1/AC2). This plan adds the
implementation strategy, key decisions, risks, and slice order. Steps live in steps.md.

## Approach

Eliminate the two clj-kondo unresolved-var warnings in
`extensions/dev-http/test/extensions/dev_http_test.clj` (`http-client/get` @572,
`http-client/post` @737) through **analysis-level registration** of http-kit's
`defreq`-generated vars — no exclusion/ignore, change confined to the http-kit
per-library clj-kondo import (AC2). http-kit's `org.httpkit.client/get|post` are
generated by the private `defreq` macro (jar line 378, calls at 388–403); clj-kondo's
jar analysis never macroexpands them, so they are absent from the namespace analysis.

### Key decisions

1. **Facility: `:lint-as`, not a hook and not `:namespaces`.**
   Add `{:lint-as {org.httpkit.client/defreq clojure.core/def}}` to
   `.clj-kondo/imports/http-kit/http-kit/config.edn` (keeping the existing
   with-channel `:analyze-call` hook). Verified empirically (clj-kondo 2025.09.19 +
   http-kit 2.8.0, jar analysis then cache-driven lint): each `(defreq verb)` in the
   jar is analyzed as `(def verb)`, registering the full verb set; `get`/`post` then
   resolve at the test-file call sites; a genuine bogus `http-client/…` var still
   warns (analysis-level, not suppression). No new file needed.
   - The `:namespaces {org.httpkit.client {get {:defined-by …}}}` var-registration
     facility suggested in implementation.md **does not exist** in clj-kondo
     2025.09.19 (no such config key; silently ignored — disproven empirically).
     Design.md's mechanism ("an analyze-call/namespace hook implementation … or a
     `:namespaces` var declaration") still holds: `:lint-as` is the chosen
     implementation inside the allowed facility set.
   - Fallback if `:lint-as` misbehaves in-repo: `:macroexpand` hook for
     `org.httpkit.client/defreq` under the same import dir (also verified).
   - Informational: linting the jar *without* `--dependencies` under this lint-as
     yields "Uninitialized var" warnings at the defreq lines. The repo lint surface
     (`bb lint` ≡ `clojure -M:lint`) never lints jars, so acceptance is unaffected.

2. **Durability: make the http-kit import dir tracked (design inconsistency).**
   `.clj-kondo/imports/` is gitignored (`**/.clj-kondo/imports/`); the design's
   committed-mechanism target `.clj-kondo/imports/http-kit/http-kit/` is currently an
   untracked local copy of the jar's `clj-kondo.exports` (identical, verified). A
   change there alone would be uncommittable, invisible to CI/other devs, and lost on
   `--copy-configs` regeneration. Resolution: in `.gitignore`, replace
   `**/.clj-kondo/imports/` with
   `**/.clj-kondo/imports/*` + `!.clj-kondo/imports/http-kit/` +
   `!.clj-kondo/imports/http-kit/**`, and commit the http-kit import dir (existing
   `config.edn` + `httpkit/with_channel.clj` + the new lint-as entry). Change remains
   confined to the import dir → AC2 holds literally; root `.clj-kondo/config.edn`
   untouched. (Pattern verified in scratch repo: http-kit tracked, sibling imports
   still ignored.)
   - Fallback (only if the above is rejected): add the lint-as to tracked root
     `.clj-kondo/config.edn` (mirrors the malli/promesa `:lint-as` convention) —
     conflicts with AC2 as written, requires an explicit design amendment.

3. **Cache rebuild is required for local AC1.**
   `bb lint` resolves dependency namespaces from the gitignored local cache
   (`.clj-kondo/.cache/v1/clj/org.httpkit.client.transit.json`, built 2026-06-29
   without the registration) — that stale analysis is the source of the two warnings
   (`--cache false` run confirms: warnings disappear, jar never re-analyzed). After
   the config change, regenerate the http-kit cache entry:
   `clojure -M:lint --lint ~/.m2/repository/http-kit/http-kit/2.8.0/http-kit-2.8.0.jar --dependencies`
   (from repo root; findings suppressed, cache written with `get`/`post`). Then
   `bb lint` is clean. For the lint surface itself, CI runs `bb lint` with no cache →
   the ns is not analyzed → trivially clean; the pinned JVM clj-kondo 2025.09.19 is the
   effective gate (consistent with implementation.md). The CI-enforceable regression
   surface is the committed test vehicle (design-step 9 option (a) via tests, slices
   7-18, non-exhaustive): `http-kit-defreq-analysis-level-resolution-test` +
   `gitignore-http-kit-tracking-ground-truth-test` +
   `with-channel-hook-semantics-guard-test` (`^:integration` in
   `components/shared-config/test/psi/shared_config/lint_config_integration_test.clj`) run via
   `bb clojure:test:integration`.

4. **No suppression, no CHANGELOG.** AC1 is analysis-level resolution; the negative
   control (bogus `http-client/…` var still flagged) is part of verification. Root
   `.clj-kondo/config.edn` keeps `:unresolved-symbol :exclude` exactly
   `[(malli.core/=>)]` (AC2). Tooling/lint config is not user-facing → no CHANGELOG
   entry per AGENTS.md user_visible rule.

## Risks

- R1 — **Gitignored target (design inconsistency).** The design's mechanism target is
  untracked local state; resolved by decision 2 (tracked http-kit import dir). If the
  gitignore change is rejected, the root-config fallback requires AC2 amendment. Flag
  for human review (design header: "No human review has occurred yet").
- R2 — **Facility assumption wrong.** implementation.md's `:namespaces` registration
  is unsupported in clj-kondo 2025.09.19; corrected to `:lint-as` (verified). No
  blocking impact; design's facility "or" is resolved by evidence.
- R3 — **Stale cache.** Without the rebuild (decision 3), `bb lint` keeps reporting the
  two warnings locally. Rebuild is a local, gitignored step; must be repeated on
  version bumps. Provenance (design-step 8): the pre-fix cache was analyzed from the
  non-pinned `http-kit-2.9.0-beta1.jar` (built 2026-06-29), not 2.8.0; the slice-2
  rebuild re-lints the pinned 2.8.0 jar explicitly. CI scope (design-step 9): the `bb
  lint` surface itself is local/cache-dependent — CI `bb lint` has no cache and never
  analyzes the jar, so it is trivially clean with or without the fix. The analysis-level
  proof is committed as `^:integration` tests (slices 7-18, option (a) via a test
  vehicle) run in CI via `bb clojure:test:integration` — no CI workflow change, but the
  regression surface is CI-enforceable (committed config + committed integration proof,
  not merely local verification).
- R4 — **Version bumps.** http-kit (2.8.0) or clj-kondo (2025.09.19) changes require
  re-verifying the registration + cache (standing design note).
- R5 — **`--copy-configs` regeneration** would overwrite the committed http-kit
  import config locally (visible as a git diff; pinned 2.8.0 keeps it stable). Do not
  regenerate.
- R6 — **No coupling with task 251** (bb.edn change): disjoint files
  (`.gitignore`/`.clj-kondo/imports/http-kit/` vs `bb.edn`).

## Slice order

1. **Slice 0 — Baseline & facility ground truth.** Reproduce the two-warning baseline;
   re-confirm the `:lint-as` facility and negative control in a scratch setup; record
   the pre-change root-config state.
2. **Slice 1 — Registration in the http-kit import.** Gitignore negation + tracked
   http-kit import dir; add the `:lint-as` entry to its config.edn.
3. **Slice 2 — Cache rebuild.** Jar analysis with `--dependencies` regenerates the
   http-kit ns cache with the registered vars.
4. **Slice 3 — AC1 verification.** `bb lint` clean for the file (both lines), errors: 0,
   no new warnings anywhere; negative control proves analysis-level resolution.
5. **Slice 4 — AC2, hygiene, commit.** Root config invariant; git status contains only
   intended files; no CHANGELOG; commit.
