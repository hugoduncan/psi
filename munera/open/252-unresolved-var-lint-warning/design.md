# clj-kondo unresolved var warnings for http-client/get and http-client/post

> Auto-generated by the context-manager post-turn tooling-friction analyzer (task 239), then refined by the design-review batch (architectural fit / ambiguity / inconsistency, 2026-08-15). No human review has occurred yet — verify before acting.

## Friction (what / why)

The linting step reports unresolved-var warnings in
`extensions/dev-http/test/extensions/dev_http_test.clj`:

- `extensions/dev-http/test/extensions/dev_http_test.clj:572:5: warning: Unresolved var: http-client/get`
- `extensions/dev-http/test/extensions/dev_http_test.clj:737:5: warning: Unresolved var: http-client/post`

This creates noise for the agent and, if "fixed" by silencing, risks masking
genuine unresolved-var errors elsewhere.

## Root cause (re-diagnosed)

The warning is **not** a missing require or dependency declaration:

- The test ns already requires `[org.httpkit.client :as http-client]`
  (`extensions/dev-http/test/extensions/dev_http_test.clj:16`).
- http-kit 2.8.0 is already declared in both root `deps.edn` and
  `extensions/dev-http/deps.edn`.

The warning exists because `org.httpkit.client/get` and `org.httpkit.client/post`
are generated by the private `defreq` macro in http-kit 2.8.0's
`org/httpkit/client.clj` (macro at line 378; `(defreq get)` / `(defreq post)` at
lines 388/391, along with the other verbs). clj-kondo's jar analysis never
macroexpands the private `defreq` call, so the generated vars are never
registered in its analysis of the namespace. `org.httpkit.client/request` is a
plain `defn` (line 231) and already analyzes without warning.

## Goal

Eliminate the two unresolved-var warnings for the dev-http test file through
**analysis-level resolution** (clj-kondo knows the `defreq`-generated vars
exist), with zero new warnings anywhere in the repo.

## Context

  extensions/): `extensions/dev-http/test/extensions/dev_http_test.clj`, and
  only `get`/`post` of the `defreq`-generated verb set; `request` is a plain
  defn and already resolves. Registration is ns-scoped to
  `org.httpkit.client`, so other namespaces/aliases are unaffected.
- The repo already has a per-library clj-kondo import mechanism for http-kit:

  `.clj-kondo/imports/http-kit/http-kit/httpkit/with_channel.clj`. A client-side

  holds only `(malli.core/=>)`; it must not gain http-client entries.

## Constraints

- Do **not** fix via a project-global `.clj-kondo/config.edn`
  `:unresolved-symbol` suppression: per `λ lint(f)` (fix > suppress(inline) >
  exclude ≫ suppress(global)) and `λ fix(bug)` (workaround ⇝ complexity), a
  global exclude would mask genuine unresolved-var errors elsewhere and create
  the false-negative noise the friction report itself cites.
- Keep the change localized to the http-kit per-library import (one rule
  cluster, minimal mechanism) rather than editing project-global
  `.clj-kondo/config.edn` for an http-kit-specific concern.
- Acceptance means analysis-level resolution of the vars, **not** warning
  silencing via exclusion/ignore.

## Mechanism (committed)

Extend the existing per-library http-kit import —
`.clj-kondo/imports/http-kit/http-kit/config.edn` — with a client-side
registration of the `defreq`-generated vars in `org.httpkit.client` (at minimum
`get` and `post`; registering the full verb set is acceptable since `defreq`
generates them uniformly), mirroring the placement of the existing server-side
`with-channel` hook in the same import config. The concrete clj-kondo facility
(an `analyze-call`/namespace hook implementation under
`.clj-kondo/imports/http-kit/http-kit/`, or a `:namespaces` var declaration in
`config.edn` with `:defined-by clojure.core/defn`) is an implementation choice
confined to the http-kit import directory; either registers the vars in
clj-kondo's analysis so the symbols resolve. The two disjoint 'or'-joined
remedies of the original Suggested change (global config update vs "ensure the
dependency is properly declared") are rejected: the dependency is already
declared, and the fix is the per-library analysis-level registration above.
