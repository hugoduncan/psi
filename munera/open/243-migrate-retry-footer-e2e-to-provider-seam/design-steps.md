- [ ] Ambiguity (plan, provider-seam wiring): plan.md conflates the two distinct context parameters of `execute-prepared-request! [ai-ctx ctx session-id prepared-request progress-queue]`. Provider resolution flows through the **first** `ai-ctx` arg only (`do-stream!` → `ai/stream-response-in` → `context-provider-registry ai-ctx`), which the current test passes as `{:provider-registry (atom {})}`. The **second** `ctx` is the app-runtime/session ctx (carries `:provider-retry-sleep-fn`, session state, retry state) and its `:provider-registry`, if any, is *not* consulted for provider resolution. Plan Slice 2/Approach ("Add a ctx helper using `create-context`… replacing whatever ctx the tests currently build") and Slice 3 ("pass the stub-provider ctx into `execute-prepared-request!`") do not state which parameter receives the stub. Specify explicitly: register the stub via `create-context {:anthropic stub}` and pass its `{:provider-registry …}` as the **first `ai-ctx` argument** (replacing `{:provider-registry (atom {})}`), leaving the second app-runtime `ctx` unchanged — so an implementer does not mistakenly merge `:provider-registry` into the session `ctx` where it has no effect.
