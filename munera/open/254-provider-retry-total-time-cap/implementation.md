  - **Window-open persistence point.** The deadline is only persisted when a retry is actually scheduled: `mark-active-retry!` (core.clj:386-392) is the sole writer of the `:retry` map + `:retry-attempt` on non-final retryable failures, so store `:retry-deadline-ms` in that same `apply-root-state-update-in!`/`session-update`. A retryable failure that immediately gives up (count cap) never schedules a retry, so never stores a deadline — and clear-active-retry! clears any stored state anyway.
  - **Clearing must cover both fns.** `clear-active-retry!` (core.clj:402-412) and its `retry-clear-needed?` guard (core.clj:395-400) both need `:retry-deadline-ms` added (guard currently checks only `:retry`/`:retry-attempt`/`:provider-retry-abort-requested?`; if a session had deadline but zeroed attempt+nil retry it could skip the clear). Top-level placement (sibling of `:retry-attempt`, model.clj:177) means the dissoc belongs in the same `->` thread that clears `:provider-retry-abort-requested?`.
  - **Schema edit.** `agent-session-schema` (model.clj) top-level, adjacent to `[:retry-attempt :int]` (model.clj:177): `[:retry-deadline-ms {:optional true} [:maybe :int]]`. Optional/maybe because absent until a window opens; initial-session (model.clj:~289) can omit it.
  - **Exhaustion distinguishability.** `failure-reason-for` (core.clj:361) currently returns a single keyword and is fed by the loop; the single give-up predicate must additionally expose which boundary fired (`:count-cap | :deadline`) into `:exhausted-reason`.   - **Truncated-delay recording.** `provider_retry_scheduled` emits `:delay-ms`/`:resume-at` from `retry-metadata` (core.clj:633-634) and `sleep-for-retry!` sleeps `:delay-ms` (core.clj:641); `retry-metadata` (model.clj:~581) computes `:resume-at = (+ now-ms delay-ms)` from the full delay.
