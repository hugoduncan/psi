# Design follow-up steps

- [x] AR1: Resolve the architecture mismatch with mementum governance. Either update the authoritative mementum/meta boundary to explicitly allow this autonomous completed-task extraction path, or revise the workflow design so it only produces approval-ready memory/knowledge candidates and does not autonomously commit `mementum/memories/` or `mementum/knowledge/` entries.
- [x] AMB1: Clarify the workflow authoring shape and file names. The design currently says `.edn + prompt .md`, but workflow docs treat `.md` as a standalone single-step workflow and same-name `.edn`/`.md` collisions as load errors. Specify whether `extract-task-knowledge` is a single `.md` prompt workflow, an `.edn` workflow with inline prompt text, or an `.edn` workflow delegating to a differently named prompt workflow, including the exact file names that will be loaded.
- [x] AMB2: Define completed-task slug resolution. Because the autonomous mementum exception is limited to completed Munera task artifacts, specify whether the workflow searches only `munera/closed/{NNN-slug}` or also `munera/open/{NNN-slug}`, what counts as "completed" for the trailing `task-lifecycle` invocation, and how the workflow behaves for missing, open-but-not-complete, or duplicate slug/path matches.
- [x] AMB3: Define the task-specific git-history boundary. "Relevant git history" should state the minimum lookup and allowed scope (for example commits touching the task directory, commits mentioning the task id/slug, and/or commit SHAs referenced from `implementation.md`) so extraction neither mines unrelated repository history nor misses code commits that belong to the completed task.
- [x] AMB4: Clarify the `task-lifecycle` terminal-output and context contract after adding the trailing extraction delegate. If `extract-task-knowledge` becomes the last step, say whether the final lifecycle result may be only the extraction summary or must also preserve the implementation-review/lifecycle outcome, and whether the extraction step should receive prior step output as context or only the original workflow input.
- [x] INC1: Reconcile lifecycle open-task extraction with the authoritative Munera/mementum completion boundary. Either require extraction only after the task is moved to `munera/closed/`, or explicitly amend the autonomous extraction exception/design to authorize the lifecycle post-review still-open case despite Munera state being location-based.
- [x] INC2: Add the missing user-visible CHANGELOG requirement to the design. The new `/delegate extract-task-knowledge` workflow and the changed `task-lifecycle` terminal behavior must be recorded under CHANGELOG `[Unreleased]` (Added/Changed as appropriate), not only documented in `doc/workflows.md`.
