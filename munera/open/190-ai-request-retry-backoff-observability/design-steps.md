# Design follow-up steps

- [x] Specify the authoritative storage/projection path for completed provider retry history: whether retry attempt records are derived from provider telemetry captures, stored under session state, or stored elsewhere; how they are keyed by session/turn/request/attempt; and which existing/new EQL resolvers expose the required session-, turn-, and request-level retry answers.
- [x] Specify how provider-boundary retry keeps active retry/backoff status visible through the existing TUI/Emacs/app-runtime session retry projection while a delay is pending, including when `:retry`, `:retry-attempt`, phase/status fields are set and cleared, and whether this replaces or preserves the old statechart retry state.
- [x] Reconcile completed retry-history storage with the existing provider telemetry split: specify whether `provider_request_started` / `provider_retry_scheduled` / `provider_request_finished` lifecycle events are retained under session state as new telemetry captures, how that differs from existing HTTP provider request/reply captures, and which retained records EQL projects from.
- [x] Align retry attempt numbering with the referenced telemetry contract/code: either keep `:retry-attempt` zero-based with first attempt `0`, or explicitly update the provider telemetry contract, metrics aggregation, existing resolvers, and UI projections to the new one-based `:attempt` semantics.
- [x] Align `provider_request_finished` failure status semantics with the existing provider metrics telemetry contract: either preserve `:status :failed` plus `:final?`/exhaustion metadata, or explicitly update the metrics/event contract and all consumers to understand `:terminal` and `:exhausted` statuses.
- [ ] Clarify retry limit semantics at the provider-request boundary: specify whether the configured retry limit counts total provider execution attempts or only retry executions, map that explicitly to the existing `:auto-retry-max-retries` / retry policy fields, and state the expected attempt numbers and exhaustion point for first attempt plus retries.
