- [x] ARCHITECTURE: Clarify the normalization boundary so textual tool-call recovery is applied once for both streaming final assembly and non-streaming assistant responses, rather than living only in the streaming accumulator or being duplicated across execution paths.
- [x] AMBIGUITY: Clarify mixed-response behavior when a capability-enabled assistant response contains both well-formed textual tool-call blocks and malformed/partial `<tool_call>` markup: whether to convert only the well-formed blocks and preserve malformed text, or treat the whole response as a no-op.
- [x] AMBIGUITY: Specify the narrow accepted grammar for textual tool-call tags, especially allowed tool/parameter name characters and case sensitivity, so parser and tests do not diverge on variants of `<function=TOOL_NAME>` / `<parameter=PARAM_NAME>`.
- [x] AMBIGUITY: Specify the exact canonical argument representation produced by the parser (JSON object string vs map/string-key equivalent) before it reaches existing tool execution, so implementation and tests assert one shape.
